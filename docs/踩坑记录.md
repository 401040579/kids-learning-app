## 部署 / GitHub Pages

### 1. 线上地址是自有域名，不是 github.io

站点跑在 **https://app.tao.irish/**（仓库根目录有 `CNAME` 文件）。
排查线上问题时别去访问 `401040579.github.io`。

### 2. Actions 机器人推送的提交，**会**自动触发 Pages 部署

> **实测日期**：2026-07-28

GitHub 官方文档有这么一句：

> "Commits pushed by a GitHub Actions workflow that uses the `GITHUB_TOKEN` do not trigger a GitHub Pages build."

**这句话对本仓库不成立。** 本仓库 Pages 是 legacy「Deploy from a branch」模式
（`build_type: legacy`，source = main / 根目录），实测机器人 push 后：

- 内建的 `pages-build-deployment`（event=dynamic）正常触发并部署成功
- 站点依次从 v62 → v63 → v64，两次受控测试都验证通过

**教训**：曾据那句文档加过一步显式 `POST /repos/{owner}/{repo}/pages/builds`，
结果造成**两个并发构建互相取消**，Pages API 状态显示 `errored`。已移除。

> 万一将来真的发现 bot 提交后站点不更新，手动补一次：
> ```bash
> gh api --method POST repos/401040579/kids-learning-app/pages/builds
> ```

### 3. 仓库权限默认 read，但 workflow 里可以自己提权

仓库设置 `default_workflow_permissions` 是 `read`，但在 workflow 文件里写：

```yaml
permissions:
  contents: write
```

即可获得写权限并成功 push，**不需要改仓库设置**。仓库设置只决定「默认值」不是「上限」。
（前提：main 无分支保护、无 ruleset，已确认；唯一例外是来自 fork 的 PR。）

### 4. 部署有延迟

推送到站点实际更新约 **1~2 分钟**。等待时别急着判定失败，给足 2 分钟。

## 视频模块

### 5. 公共 CORS 代理已全面失效，不要再依赖

> **实测日期**：2026-07-28

逐个测过 7 个免费公共 CORS 代理，**全部不可用**：

| 代理 | 状态 |
|---|---|
| corsproxy.io | 403 |
| api.allorigins.win | 超时 / 522 |
| api.codetabs.com | 超时 |
| thingproxy.freeboard.io | 超时 |
| api.cors.lol | 429 |
| proxy.cors.sh | 404 |

**所以：不要再引入任何运行时 CORS 代理依赖。** 需要跨域数据就在 CI 里预生成静态文件
（见 `scripts/fetch_videos.py` + `.github/workflows/update-videos.yml`）。

### 6. YouTube RSS 硬上限 15 条

`youtube.com/feeds/videos.xml?channel_id=UC...` 永远只返回**最新 15 条**，这是接口本身的限制，
不是代码问题。目标频道有 435 个视频，靠 RSS 永远拿不全。
拿全量要走播放列表页 + innertube 续页（`scripts/fetch_videos.py` 已实现）。

### 7. 「静默截断」比「抓不到」危险得多

抓取脚本最初只防「一条都没抓到」。但 YouTube 限流的典型表现是
**返回 HTTP 200 + 合法 JSON，内容却是空的**——这会让列表从 435 条悄悄变成 300 条，
校验全过、CI 全绿，还会 bump SW 版本**主动把截断结果推到所有设备**。

现在设了四道保护，任一触发都退出非 0 且**绝不覆盖已有文件**：

1. 任何频道抓到 0 条
2. 某页解析出 0 条但 YouTube 仍返回续页 token
3. 撞到 `MAX_PAGES` 上限时续页 token 还在
4. 新列表比已有文件少 10% 以上
5. （附加）`--max-pages` 局部抓取拒绝写正式文件

**原则**：宁可 CI 红一次让人来看，也不能让孩子的内容悄悄变少。

## 前端 / CSS

### 8. 新版 Chrome 把 `display: -webkit-box` 强制改写成 `flow-root`

> **实测日期**：2026-07-28

经典的两行截断写法在新版 Chrome 上失效：

```css
display: -webkit-box;
-webkit-line-clamp: 2;
-webkit-box-orient: vertical;
overflow: hidden;
```

`getComputedStyle(el).display` 返回的是 **`flow-root`**，连**内联设置也会被改写**，
于是 `line-clamp` 完全不起作用，文字被拦腰硬切。

**解法**：保留 `-webkit-box`（Safari/iOS 仍然有效，还能出省略号）+ 加标准 `line-clamp`，
再用**固定高度**兜底：

```css
height: calc(2.16rem + 8px);   /* 2 行 × line-height + 上 padding */
```

### 9. `overflow: hidden` 裁的是 **padding 盒**边缘，不是内容盒

固定高度加上后仍会看到被截断的第 3 行从底部露出来——因为内容会渲染进 `padding-bottom` 区域，
而 `overflow: hidden` 不裁那里。

**解法**：截断元素的 `padding-bottom` 必须为 **0**，底部留白挪到父元素上。
见 `.video-thumb-title` / `.video-thumb-card`。

### 10. iOS Safari 没有 `scrollend` 事件

首页分屏翻页的指示器同步不能依赖 `scrollend`（Chrome/Firefox 有，WebKit 至今没有）。
改用 `scroll` 事件 + `requestAnimationFrame` 节流，算
`Math.round(scrollLeft / clientWidth)`。见 `js/homeScreen.js`。

### 11. `scroll-snap-type: x mandatory` 容器上原生 `scrollTo({behavior:'smooth'})` 会卡死

吸附逻辑会打断平滑滚动动画，导致滚动位置纹丝不动（指示器却切了，看起来像"点了没反应"）。

**解法**：自己用 rAF 每帧直接赋值 `scrollLeft` 做缓动。见 `HomeScreen.smoothScrollTo()`。

另外：`.page` 切换用的是 `display: none`，**会丢掉 `scrollLeft`**，
所以回到首页时必须重置（`HomeScreen.onShow()`），跨页跳转要用 instant 而非 smooth。

## PWA / Service Worker

### 12. SW 是 cache-first，不 bump 版本号更新就到不了用户手上

`sw.js` 命中缓存就不走网络。所以哪怕新文件已经部署上线，**老设备上的 SW 依然一直返回旧缓存**。

任何资源变更都必须同步 bump `CACHE_NAME` 里的 `kids-learning-vNN`。
视频列表由 CI 更新，所以 CI 里也自动 bump（`.github/workflows/update-videos.yml`）。

### 13. 相对路径与绝对路径能命中同一个缓存条目

SW 预缓存的是 `/data/videos.json`，运行时 `fetch('data/videos.json')` 用的是相对路径。
**实测两者命中同一条目**（站点挂在根目录，解析结果都是
`https://app.tao.irish/data/videos.json`）。

⚠️ 但如果将来改成子路径部署，这两处必须同步改。

### 14. 从 precache 列表移除文件前，先确认文件还在

`cache.addAll()` 只要有一个 URL 404，**整个 SW 安装就失败**。
删文件时务必同步从 `sw.js` 的 `urlsToCache` 里移除。

## 调试环境

### 15. `python3 -m http.server` 会在并发请求下挂掉

本地调试时它是单线程的，本项目有 40+ 个 script 标签，浏览器并发拉取时服务进程会直接死掉。
表现为：**页面加载一半、CSS/JS 报 `ERR_CONNECTION_REFUSED`、页面完全没样式**。

看到这种现象先检查服务是否还活着，别急着怀疑代码：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

### 16. 隐藏的浏览器标签页会节流定时器

Browser pane 被隐藏时 `setTimeout` 最小间隔被钳制到 1 秒，`requestAnimationFrame` 和
`IntersectionObserver` 干脆不投递回调。写自动化验证脚本时循环次数要留余量，
别把「拿不到回调」当成代码 bug。

### 17. `display: none` 的元素会让 IntersectionObserver 误判

零尺寸矩形会被 Chrome 判成 `isIntersecting = true`，导致「滚动到底自动加载」在
用户还没进页面时就自我级联触发（实测一进探索页就已经渲染了 96 张卡而非 24 张）。

**解法**：回调里加 `if (entry.boundingClientRect.height <= 0) continue;`
